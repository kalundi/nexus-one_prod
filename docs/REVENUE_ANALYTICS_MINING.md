# Revenue Analytics Mining

This project now exposes a secure revenue analytics surface for the data generated by the Booking App and Driver App.

## Why this exists

Operational data already lands in core tables such as:
- `bookings`
- `trip_status_history`
- `audit_log`
- `gps_positions`

The new analytics routes provide a finance-safe and executive-safe way to mine revenue and projection data without exposing unnecessary rider PII in normal reporting responses.

## Secure API routes

### 1. Aggregated analytics JSON

`GET /api/admin/analytics/revenue?start=YYYY-MM-DD&end=YYYY-MM-DD&groupBy=day`

Allowed roles:
- `ADMIN`
- `EXECUTIVE`
- `BILLING`

Returns:
- `period`
- `summary`
- `series`
- `breakdowns.byService`
- `breakdowns.byStatus`
- `breakdowns.byPaymentStatus`
- `breakdowns.bySource`
- `governance`

Projection fields include:
- `estimatedRevenue`
- `cashCollected`
- `outstandingBalance`
- `depositsCaptured`
- `cancellationFees`
- `averageTicket`
- `projectedPeriodRevenue`

### 2. Controlled CSV export

`GET /api/admin/analytics/revenue-export?start=YYYY-MM-DD&end=YYYY-MM-DD`

Allowed roles:
- `ADMIN`
- `EXECUTIVE`
- `BILLING`

CSV fields:
- `reference`
- `trip_date`
- `trip_time`
- `service`
- `booking_source`
- `status`
- `payment_status`
- `estimated_fare`
- `deposit_amount`
- `balance_due`
- `cancellation_fee_amount`
- `driver_name`
- `vehicle_unit`

This export intentionally avoids passenger name, phone, email, and notes.

## Security controls

The analytics surface is protected by:
- role-based access control through authenticated API sessions
- audit logging for report views and exports
- PII minimization in default analytics responses
- export scoping by explicit date range

Audit entries recorded:
- `REPORT / revenue-analytics / VIEWED`
- `REPORT / revenue-export / EXPORTED`

## Recommended finance workflow

1. Use the JSON route for dashboards, revenue trend charts, and projection views.
2. Use the CSV export route for accounting reconciliation and deeper spreadsheet analysis.
3. Restrict credentials for these routes to executive and billing staff only.
4. Periodically review `audit_log` for report access patterns.

## Projection notes

For current-month queries, `projectedPeriodRevenue` is calculated from the month-to-date estimated revenue run rate.

This is useful for:
- revenue pacing
- deposit conversion tracking
- outstanding balance monitoring
- service mix analysis

## Data governance next steps

Recommended next enhancements:
- add a dedicated executive dashboard page that consumes `/api/admin/analytics/revenue`
- add cohort views for repeat riders and facility partners
- add a warehouse or nightly snapshot table if historical trend retention becomes more complex
- add retention policies for GPS detail if only summary analytics are needed long-term
