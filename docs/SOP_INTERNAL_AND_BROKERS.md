# Standard Operating Procedure (SOP) for Internal Users and Brokers

## Purpose
This SOP defines how internal users and brokers submit, review, and manage broker transport requests within the Nexus Medical Transit broker workflow.

---

## 1. Roles and Responsibilities

### Internal Users
Internal users include dispatchers, administrators, operations staff, billing staff, and executives.

Responsibilities:
- Review incoming broker requests
- Approve, reject, or request more information for requests
- Maintain broker master records and broker pricing
- Monitor current-period broker activity and exports
- Ensure broker requests are handled in a timely and consistent manner

### Brokers
Brokers submit trip requests and pricing information for medical transport services.

Responsibilities:
- Submit ride requests with pickup, destination, date, time, and rate details
- Provide accurate pricing information for review
- Respond to follow-up requests from internal users when clarification is needed
- Use the approved workflow so requests are routed correctly and quickly

---

## 2. How to Submit a Broker Request

### Option A: Manual Submission via Internal System
Internal users can submit a broker request through the broker request workflow in the application.

Required fields:
- Pickup location
- Destination location
- Trip date
- Trip time
- Service type
- Broker quoted rate
- Platform calculated rate
- Broker name

### Option B: Broker Email Submission
Brokers may submit requests by email using a structured format.

Required email content:
- Pickup
- Destination
- Date
- Time
- Service
- Rate quote

Example:
```text
Pickup: 123 Main St, Boston MA
Destination: 456 Oak Ave, Quincy MA
Date: 2026-08-15
Time: 14:30
Service: MEDICAL_TRANSPORT
Rate Quote: $85.00
```

---

## 3. Standard Workflow

### Step 1: Request Intake
- The request is created as a broker request in the system.
- The system automatically assigns the initial status of AUTO_CONFIRMED.
- Dispatch is notified immediately.

### Step 2: Review
Internal users review the request for:
- Accuracy of pickup and destination
- Rate variance between broker quote and platform rate
- Completeness of required fields
- Any missing information

### Step 3: Action
Internal users can:
- Approve the request
- Reject the request
- Mark it as needing more information

### Step 4: Documentation
The system records:
- Reviewer name
- Review timestamp
- Review notes
- Final request status

---

## 4. Internal User SOP

### Access
Internal users should sign in through the authorized internal portal using their assigned credentials.

### Daily Responsibilities
1. Review new broker requests promptly.
2. Confirm pickup, destination, date, and rate details.
3. Compare broker quote to the platform calculated rate.
4. Approve or reject the request according to policy.
5. Add notes if follow-up is required.

### Escalation
Escalate unusual or high-variance requests to operations leadership or the dispatch manager.

### Record Keeping
All actions should be documented in the request record, including approval decisions and notes.

---

## 5. Broker SOP

### Submission Expectations
Brokers should provide complete and accurate request details at submission time.

### Required Information
Each request should include:
- Correct pickup and destination addresses
- Accurate trip date and time
- Correct service type
- A realistic rate quote

### Best Practices
- Submit requests as early as possible to allow review time.
- Use the structured email format when sending by email.
- Keep contact information current for follow-up.
- Respond quickly to requests for clarification.

### What Happens After Submission
- The request enters the review workflow.
- Internal users evaluate it.
- The broker is notified through the normal operational process if follow-up is needed.

---

## 6. Quality Standards

Requests should be considered complete only when:
- All required fields are present
- Travel details are accurate
- Pricing is reasonable and documented
- The request is routed to the correct internal team

---

## 7. Common Issues and Resolution

### Missing Information
If a request is missing pickup, destination, date, or rate details, internal users should request clarification from the broker.

### Rate Variance
If the broker quote differs significantly from the platform rate, internal users should review the request carefully and document the reason for approval or rejection.

### Email Parsing Problems
If an email submission is not parsed correctly, the sender should resend the email using the example structure above and confirm the message is not missing required details.

---

## 8. Approval and Compliance

All broker requests must follow the same review standards to ensure:
- Consistent handling
- Accurate pricing review
- Auditability of decisions
- Proper operational oversight

---

## 9. Summary
This SOP ensures that both internal users and brokers follow a clear and consistent process for submitting, reviewing, and managing broker requests in the Nexus Medical Transit platform.
